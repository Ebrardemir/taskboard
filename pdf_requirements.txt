Minimum smoke test senaryoları (zorunlu)
Endpoint yolları projeye göre değişebilir (örn. /api/...). Aşağıdaki maddelerdeki amaç, akışı test
etmektir.
<entity>, sizin seçtiğiniz “ana varlık”tır (örn. Task, Note, Event, Issue).
1. Register (kayıt) → 201
2. Login (giriş) → 200 (session/cookie veya token oluşumu doğrulanır)
3. Auth gerekli endpoint: login olmadan → 401
4. Ana varlık oluşturma (Create) (POST /<entity>) → 201
Response’ta en az id ve zorunlu alan(lar) doğrulanır (örn. title).
5. Ana varlık listeleme (Read-list) (GET /<entity>) → 200
Bir önceki adımda oluşturulan kaydın listede olduğu doğrulanır.
6. Ana varlık okuma (Read-single) (GET /<entity>/:id) → 200
7. Ana varlık güncelleme (Update) (PATCH /<entity>/:id) → 200
Güncellenen alanın gerçekten değiştiği doğrulanır.
8. Ana varlık silme (Delete) (DELETE /<entity>/:id) → 204
Sonrasında GET /<entity>/:id → 404
9. Validation (hatalı istek): geçersiz veri ile create/update → 400
10. Admin-only endpoint: user ile → 403, admin ile → 200
Unit test
Unit test, tek bir fonksiyonun/servisin doğru çalışıp çalışmadığını kontrol eden “küçük” testtir. Burada amaç;
DB’ye gerçekten bağlanmadan, ağ isteği atmadan, hızlı çalışan testlerle iş kurallarınızı güvenceye almak.
En az 10 adet unit test aşağıdaki başlıkları içerecek şekilde yazılmalıdır:
Validation / iş kuralları: zorunlu alanlar, sınır değerler, format kontrolleri
Yetkilendirme kararı: admin/user rolüne göre izin ver/engelle mantığı
Hata durumları: bulunamadı, yetkisiz, çakışma vb. (servis seviyesinde)
Servis katmanı mantığı: “ana varlık” CRUD iş mantığı (route/controller değil)
